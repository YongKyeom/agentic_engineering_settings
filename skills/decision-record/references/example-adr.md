# ADR-0002: 이벤트 저장소를 Postgres로 전환 — 파일 기반 로그의 동시성 한계 해소

- 상태: 유효 (구현 완료)
- 결정일: 2026-03-14
- 관련: [0001-event-driven-pipeline.md](./0001-event-driven-pipeline.md), [../architecture.md](../architecture.md) §2

## 1. 배경

파이프라인 이벤트를 JSONL 파일로 append하는 현 구조는 단일 워커 전제다.

실측으로 확인된 문제(2026-03-12):

- 워커 2개 동시 실행 시 이벤트 유실 재현 — 부하 1k 이벤트에서 7/100회.
- 파일 lock 도입 실험은 유실은 막았지만 처리량 41% 하락.

## 2. 결정

| # | 결정 | 핵심 |
|---|---|---|
| D1 | 이벤트 저장소 = Postgres 단일 테이블 | append-only, `INSERT`만 허용. UPDATE/DELETE 금지 |
| D2 | 스키마 = (id, ts, type, payload JSONB) | payload 검증은 쓰기 경로의 Pydantic 모델이 담당 |
| D3 | 조회는 read-only view로만 | 소비자가 원본 테이블에 직접 붙지 않는다 |

## 3. 기각한 대안

| 대안 | 기각 사유 |
|---|---|
| SQLite + WAL | 워커를 컨테이너로 분리하는 로드맵과 충돌 — 파일 공유 전제가 다시 생긴다 |
| Kafka | 운영 부담이 팀 규모 대비 과함. 현재 처리량(≤50 evt/s)에 과설계 |
| 파일 lock 유지 | 실측 처리량 41% 하락. 근본 원인(단일 파일 공유)이 미해결 |

## 4. 근거

- 동시성 실측(2026-03-12): 워커 2개 + 부하 1k 이벤트에서 유실 7/100회 재현.
- Postgres PoC(2026-03-13): 같은 부하에서 유실 0, p95 쓰기 지연 4ms.
- [../architecture.md](../architecture.md) §2 "저장소는 워커 수에 독립" 원칙과 부합.

## 5. 영향

- 장점: 동시 워커 제약 제거, 조회 표준화(SQL).
- 비용: 로컬 개발에 Postgres 컨테이너 필요. CI 셋업 수정.
- 후속: migration 스크립트(JSONL → 테이블), 기존 소비자 2곳 view 전환.
- 검증: 완료 — 동시성 PoC. 남음 — 운영 부하 24h soak.

## 6. 개정 이력

- 2026-03-14: 신설.
- 2026-03-20: 구현 완료. D3 보강 — 소비자 전환 완료에 따라 원본 테이블 직접 접근 권한 회수.
