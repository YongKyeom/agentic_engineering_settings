# Deep Research

질문에 답하는 데 필요한 근거를 여러 소스에서 확인하고, 확인된 사실·해석·불확실성을 구분해 제시한다. 사용자가 정한 범위·형식·검색 제한을 따른다.

## Usage

```
/deep-research <topic or question>
```

## 조사 절차

1. **판단할 질문 정리.** 답이 바뀔 수 있는 조건, 비교 기준, 기간·지역·버전을 확인한다. 중요한 미정 조건만 질문하고, 나머지는 합리적인 가정을 밝히고 진행한다. 고정된 소스 수나 분량을 목표로 삼지 않는다.
2. **근거 탐색.** 제공 자료와 연결된 소스부터 확인하고, 필요한 웹·문서·논문을 현재 사용 가능한 검색·읽기 도구로 찾는다. 독립적인 검색은 묶어 실행할 수 있지만, 병렬 에이전트는 유용하고 허용될 때만 사용한다.
3. **원문 확인.** 검색 결과·요약·초록은 탐색 단서로 쓰고, 최종 주장의 근거가 되는 페이지·논문·문서의 해당 부분을 읽는다. 접근하지 못했다면 그 한계를 밝히고 읽은 것처럼 인용하지 않는다. 표·그림·부록이 결론을 좌우하면 함께 확인한다.
4. **교차 검증.** 중요한 사실과 비교 결과를 독립적인 근거와 대조한다. 같은 보도자료를 재인용한 여러 글은 하나의 근거 계열로 본다. 출처가 하나뿐이면 그 한계를 적는다.
5. **종합과 종료.** 핵심 질문에 먼저 답하고 근거·조건·상충 결과를 이어 쓴다. 결정에 필요한 근거가 충분해지거나 추가 검색의 가치가 낮아지면 멈추고, 남은 공백을 명시한다.

## 근거 판단

- 기술적 주장은 공식 문서·명세·원 논문·원 데이터 등 1차 자료로 뒷받침한다. 다른 주제도 가능한 한 원자료를 우선하고, 방법·범위·이해관계·직접성을 기준으로 품질을 평가한다. 2차 자료의 해석은 원자료의 결과와 구분한다.
- 시의성은 질문에 맞춘다. 가격·법·제품 동작·직책처럼 바뀌는 정보는 현재 자료를 확인하고 기준일·버전·관할을 적는다. 게시일·개정일과 실제 사건·데이터 수집 시점을 구분한다. 오래됐다는 이유만으로 유효한 원 연구를 버리지 않는다.
- 출처가 충돌하면 정의·대상·표본·방법·기간·버전 차이를 먼저 확인한다. 더 직접적이고 적합한 근거가 있다면 채택 이유를 설명하고, 해소되지 않은 충돌은 그대로 남긴다. 기계적으로 양쪽을 동등하게 취급하거나 평균내지 않는다.
- 수치에는 단위·분모·비교 조건을 보존한다. 상관관계를 인과로 바꾸지 않는다. 계산·추론·권고는 출처가 직접 말한 사실과 구분하고, 추론의 전제를 밝힌다.
- 근거를 찾지 못했다는 사실은 효과나 사건이 없다는 증거가 아니다. 확인할 수 없는 결과·인용·합의를 만들어내지 않는다.

## 인용과 결과

핵심 사실과 결론에는 이를 직접 뒷받침하는 출처를 문장 가까이에 연결한다. 웹 자료는 검색 결과 URL 대신 원 페이지의 제목과 링크를 쓰고, 내부 자료는 사용자가 확인할 수 있는 문서·파일·절을 식별한다. 인용 하나가 문단의 서로 다른 주장을 모두 뒷받침한다고 가정하지 않는다.

직접 인용은 원문과 정확히 맞추고 인용임을 표시한다. 번역은 번역임을 밝히며, 출처별 인용·재사용 한도와 접근 제한을 지킨다. 출처 목록이 필요하면 실제 사용한 자료만 포함한다.

일반적인 결과는 **답변 → 주요 근거·비교 → 한계·다음 판단에 필요한 정보** 순서로 구성한다. 복잡한 비교에는 표를 쓰되 사용자 형식이 우선이다. 간결함 때문에 결론을 판단하는 조건이나 근거를 생략하지 않는다. 별도 리포트 파일 생성, 게시, 계정 변경은 조사 자체의 일부로 가정하지 말고 요청한 저장 위치와 권한을 따른다.
