# Handoff Docs

이 폴더는 세션 인수인계 메모를 로컬에 남기기 위한 공간입니다.
Handoff는 다른 Agent나 사용자에게 넘길 수 있는 최소 전달 패키지입니다.
사용자가 새 세션이나 다른 담당자에게 인계를 요청할 때 별도 문서를 만듭니다.
평소에는 기존 같은 주제의 Handoff를 갱신하고, 문맥이 길어졌다는 이유로 새 파일을 만들지 않습니다.
기존 Handoff가 없으면 별도 문서 요청 전까지 대화에 상태·결과·다음 조치를 남깁니다.

이 폴더도 `plan/`과 같은 기준을 따릅니다.
폴더 구조는 Git에 남기지만, 개별 handoff 파일은 기본적으로 commit하지 않습니다.

## 사용 목적

- 긴 세션의 현재 상태를 짧게 보존합니다.
- 다음 세션이 전체 대화 기록을 다시 읽지 않고 이어서 작업하게 합니다.
- 변경한 파일, 실행한 명령, 결정한 사항, 남은 위험을 놓치지 않게 합니다.
- 사람, Codex, Claude 사이에 작업 맥락을 넘깁니다.

## Git 추적 기준

- 이 폴더 자체는 Git에 유지합니다.
- `.gitkeep`, `README.md`, `AGENTS.md`는 commit합니다.
- 개별 handoff 파일은 기본적으로 commit하지 않습니다.
- 사용자가 명시적으로 공유 문서로 남기라고 했을 때만 handoff 파일을 commit합니다.
- 장기적으로 보존해야 하는 기술 결정은 `docs/decisions/`로 옮깁니다.

## Handoff Template

작업 규모에 따라 관련 절을 합칠 수 있습니다. 알려지지 않은 담당·일정·합의·검증은 미확인으로 남깁니다.

```md
# Handoff: Title

- 갱신일: YYYY-MM-DD
- 독자: 다음 담당자 또는 검토자
- 대상 프로젝트·위치: 실제 경로 또는 저장소
- 브랜치·기준 버전: 확인한 값 / 미확인
- 문서 상태: 초안 / 검토 중 / 합의됨 (확인된 경우)

## 개요

현재 목적·결과·단계와 이 인계가 다루는 범위를 짧게 적습니다.

## 현재 현황과 다음 조치

| 작업 | 담당 | 상태 | 결과·근거 | 다음 조치·재개 조건 |
|---|---|---|---|---|
| 기능 단위 | 확인한 담당 / 미정 | 진행 | 실제 결과 또는 미검증 | 바로 할 일과 선행 조건 |

작업 상태는 `예정 / 진행 / 대기 / 완료 / 제외`를 사용하며 문서 상태와 구분합니다.

## 범위와 우선순위

대상·순서·의존 관계·완료 기준을 적습니다. 이미 정해진 범위만 요약하고 미확인 일정을 만들지 않습니다.

## 결정·확인과 관련 문서

- 확정 결정·제안·미결 사항을 구분하고 이유와 필요한 담당을 적습니다.
- 장기 작업이면 Plan 링크와 현재 단계·차단 사유·다음 조치를 남깁니다.
- 상세 스펙·담당·검증 표·시행착오는 Plan에 유지하며 여기에는 반복하지 않습니다.

## 변경과 핵심 파일

- `path/to/file` - 무엇을 왜 바꿨고 다음 담당자가 먼저 볼 이유
- 조건·예외·책임·복구 경계를 필요한 범위에서 설명합니다.

## 검증

- 실제 실행한 명령·대상·결과와 근거 경로
- 수동으로 확인한 내용
- 실행하지 못한 검증과 그 한계

## 재개 정보와 남은 위험

- 바로 실행할 첫 조치, 차단 사유·재개 조건
- 필요한 경우 실행 중 작업 ID·로그 위치
- 현재 가정과 미결 위험, 로컬 산출물 처리 여부
- 이전 인계 참조: 없음 / `YYYYMMDD_<topic>-handoff.md`

```

## 작성 기준

- 새 세션이 바로 이어서 작업할 수 있을 만큼 구체적으로 씁니다.
- 실행하지 않은 검증을 실행했다고 쓰지 않습니다.
- 새 handoff를 만들 때는 이전 handoff의 유효한 결정, 변경, 위험, 다음 액션을 이어받고 완료되거나 대체된 항목을 명시합니다.
- 불필요하게 긴 로그를 붙이지 말고, 핵심 결과만 요약합니다.
- 파일로 남길 때 권장 위치는 `docs/handoff/YYYYMMDD_<주제>-handoff.md`입니다.
